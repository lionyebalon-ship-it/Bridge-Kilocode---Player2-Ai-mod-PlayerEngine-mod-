# NPC Characters — guide

Player2NPC companions are driven by a small character roster served by the
bridge. Each companion NPC can have its own personality, and in-game you pick
which one appears (the H menu). All characters share the pinned model
(`nvidia/nemotron-3-super-120b-a12b:free`) — **one brain, many faces**. The
model is a single global setting in `bridge/config.json`; characters do not
bind models.

## The roster file: `bridge/characters.json`

```json
{
  "characters": [
    {
      "id": "kilo",
      "name": "Kilo",
      "short_name": "KILO",
      "greeting": "Hey there! I'm your companion on this server. What are we up to today?",
      "description": "You are a helpful, concise Minecraft companion AI agent.",
      "voice_ids": [],
      "meta": { "skin_url": "" }
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `id` | **Required by the mod.** Persists the companion's state. Auto-generated by the CLI (slug of the short name, e.g. `bob`) and backfilled by the bridge at serve time when missing. Keep ids stable — renaming an id orphans the companion's stored state. Collisions get `-2`, `-3`, … suffixes. |
| `name` | Display name shown in menus. |
| `short_name` | The by-name chat gate: your in-game message must contain this name (or the name) for the companion to answer. |
| `greeting` | Sent by the NPC on spawn. |
| `description` | Feeds the NPC's system prompt — this is where the personality actually lives. |
| `voice_ids` | Voice IDs for TTS (stubbed in the bridge; leave `[]`). |
| `meta.skin_url` | Optional skin texture URL. |

## Managing the roster (CLI)

```bash
python3 bridge/characters.py list
python3 bridge/characters.py add --name "Bob the Miner" --short "BOB" \
  --greeting "Hey there, name's Bob." --description "A gruff but friendly miner."
python3 bridge/characters.py show --name "Bob the Miner"
python3 bridge/characters.py remove --name "Bob the Miner"
```

- `add` requires `--name`, `--short`, `--greeting`, `--description`.
- Optional `--id` pins the id (validated: `^[A-Za-z0-9_-]+$`, ≤64 chars);
  without it the id is the slug of `--short` (e.g. `bob`). `--force` allows
  overriding an existing id.
- `remove` matches on `name` OR `short_name`.
- `--path` points the CLI at a different roster file (used by tests).

## Hot reload

The bridge reads the roster on every `/v1/selected_characters` call and reloads
it automatically when the file's mtime changes — **no bridge restart needed**.
Edit `characters.json` by hand or via the CLI, then reopen the in-game H menu
to see the new cast.

## Troubleshooting

- **NPC won't spawn / "Persisted companion state was unavailable or rejected"** —
  the character has no `id`. The mod aborts spawning for id-less characters.
  Add one with `--id` or delete the field and let the bridge backfill it on the
  next serve (check `curl -s http://127.0.0.1:9800/v1/selected_characters`).
- **H menu shows no characters** — check the roster is being served:
  `curl -s http://127.0.0.1:9800/v1/selected_characters`, and confirm
  `bridge/characters.json` is valid JSON with a non-empty `characters` array.
- **The NPC ignores you in chat** — your message must contain the companion
  name (the by-name gate): e.g. start with "Kilo, …".
